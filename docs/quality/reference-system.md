# 动作参考与自动化质量数据规范 v1

本规范是 Windows 独立基础设施，不修改 `motion-workflow.md` 的 owner gate。现有高位下拉 M0/M1 首报、冻结哈希和 FAIL 结论保持原样；这里的脚本不能将它们升级为 PASS。

## 每条参考资料的最低信息

稳定 id、原题名、作者/年份（可核实时）、DOI/URL、读取日期、读取层级（摘要/全文/测量数据/工程不变量）、动作变式、适用人群/负荷/握法、支持与不支持的具体结论。许可/使用条件要区分“允许链接”与“允许下载、复制、二次发布”。摘要不等于已读全文，论文图片不自动成为可再发布动作资产。

本轮 `references/lat-pulldown.json` 登记两篇已核验摘要。它们是语境来源，尚不是可逐帧比较的真值轨迹。不要从群体 EMG 平均值生成个人刺激百分比。未来有权使用的参考录像另登记原文件哈希、许可、机位/内外参、帧率、时钟、标记定义、遮挡、衣物与负荷；二维投影不直接变成三维关节角。缺少这些信息时保留 INCONCLUSIVE。

## 数据如何流转

1. 指定不可变候选 SHA 和 GLB SHA256。沿用既有 freeze / measure adapter，候选和工具版本分别记录。
2. 以 `glb-model-y-up-metres` 输出位置和 world/model 四元数 xyzw；scene 外层缩放不得混入。保留原始测量 JSON/CSV，追加 wrapper 只补 schema/provenance。
3. `motion_contract.py` 检查采样数（至少 21）、单调秒时钟、必需关节、有限值、单位四元数和元数据。q/-q 表示同一旋转，不以符号跳变判错。
4. 仅在有解剖轴/角度定义、参考、适用范围时增加 `angleLimits`；输入样本要有对应 `angles_deg`。真实关节异常与固定骨长等工程不变量分开报告。空 range 代表未建立，不代表人体范围通过。
5. 原有 trajectory-check 保留长度/相邻采样连续性指标；GLB 验证器检查真实资源。合成负例验证“坏数据会失败”，防止只测成功路径。
6. 数字不替代原生视频/多视角和独立专业评审。姿态接触、组织碰撞、肩胛协调等无法由该 contract 证明；owner gate 仍在原流程中执行。

合成单元测试不伪装为人类数据。测试区间 `[0,10]` 只证明越界检测，不是生理阈值。参考 profile 更新应单独评审，附原出处和校准说明，不由实现者静默放宽阈值以获取绿色检查。

## 当前风险与下一证据

- P1 B01/B02/V01 继续保留，待用户指定 M2 修复范围。
- K02 手掌/拇指接触、肩带解剖轴、接触和碰撞仍缺少可靠标定；不能因 IK 标记接近而关闭。
- Mac 原始录像路径在 Windows 不存在，本轮不伪造迁移、不重新制作旧 M0/M1。后续经用户授权共享原始 evidence bundle 后可做哈希核验。
- Windows 性能结果使用核显，独显与 Mac 需各自同条件测量。
- 新动作需专属 reference profile / adapter / acceptance contract，本轮没有新增训练动作。
