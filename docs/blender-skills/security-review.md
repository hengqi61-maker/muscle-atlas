Pinned source `71d031dab8bc6729504d11a78cbe91945401045f`, MIT. `upstream-inventory.json` lists all **22 skills**, dependencies/scripts and reviewed-file SHA256. Full read of upstream AGENTS, the seven requested SKILL.md documents, selected core/pipeline/QA scripts, shared `_bpyx.py`, both installers, requested rigging/animation/export/render implementations and the relevant test harness/tests; static operation search over tools and requested paths. ## Code evidence and decisions

| Skill / component | Existing project comparison | Decision and concrete reason |
|---|---|---|
| blender-core | Canonical pipeline already pins Blender and uses strict Python exits | Reusable API reference and disposable command runner only; its discovery picks newest executable unless env pinned, so our runner requires explicit binary |
| pipeline-automation | Existing native build/manifest/GLB validator already stronger for anatomy | Reusable inventory with adapter; cannot replace build. `batch_process.py:load` resets/open scenes; `_module` imports arbitrary paths; `run` catches per-file exceptions, empty input gives `all([])=True`. Our fixed input/operation and exact-one-record check prevent these false-positive cases |
| asset-qa | Full 121-frame all-triangle pipeline checks rest-to-pose shape changes | Additive topology/island diagnostic on fixture only. `qa_check.py:run` returns `ok:true` separately from `pass`; >300000 triangles skips z-fighting/floating and can return pass, vertex sampling/64ray bound are not exact collision. Generic floating-island errors are not valid anatomy truth. Never replace original geometry gates |
| character-rigging | Existing explicit canonical matrices/attachment registry differ from Rigify | Read-only/not installed. `bind_mesh.py:run` removes armature modifiers; auto heat failure silently proxies, clears groups, removes small influences and normalizes. `rigify_build.py:game_skeleton` deletes same-name object and retargets meshes; `stress_poses.py` rewrites pose/action. These would destroy calibration/provenance or become workaround debt if used blindly |
| animation | Existing observed quaternion channels and independent Clip reuse | Redundant/needs adapter, not installed. `bake_action.py:run` deletes same-name actions/NLA tracks, mutates constraints, self-bake clears constraints; cannot apply without isolated before/after channel proof |
| export-pipelines | Current exporter explicitly preserves extras/identity and source weights | Conflicting defaults, not installed: `GLTF_BASE` has `export_apply=True`, `export_extras=False`, 4 influences, deform-only bones. `web` adds compression. | rendering | Existing native/Three actual multi-view evidence already complete | Reference only, not installed. `render_batch.py` chooses GPU automatically; video return `ok = exists(all) or media=='VIDEO'` can report success without file checks. | review_shots | Temporary camera/wire objects and hide state are managed | Script vendored as part of QA but **not executed or approved for production**: temporary visibility isn't a geometry fix; wire mode sets original object color without restoring it, and media format restoration is incomplete. Prefer own disposable render, no saved scene mutations |

## Trust boundaries

Upstream AGENTS says **“Run scripts; don't read them.”** Rejected: user expressly requires inspection. Upstream QA advice to delete hidden parts, merge duplicates, fix every error and repeat to pass is rejected for original anatomical source data. The local `.agents/AGENTS.md` makes this explicit and no upstream AGENTS was installed.

Upstream `install/install.sh` defaults to user scope and both install/uninstall invoke `rm -rf "$dst/$name"`; PowerShell removes existing target recursively. Neither executed. The official reviewed skill-installer's explicit project `--dest`, pinned SHA and git method installed exactly three skills; no fallback/mirror/retry was required. Included shared helper copies match the reviewed MIT original. Core subprocess runner uses argument arrays without shell, but permits arbitrary script/expr paths if directly invoked; its code is reference, our strict runner is the supported entry point. Selected helpers contain no network requests, package installs, shell commands or filesystem deletion; Blender APIs do mutate in-memory scene state, and optional `_bpyx.cli --save` can overwrite supplied paths—our entry point does not expose it.

No runtime network or third-party hooks used. This is code inspection plus controlled execution, **not a sandbox guarantee**. Read-only imported assets can carry Blender handlers, so untrusted .blend inputs are prohibited; our fixture is self-generated, factory-startup and disable-autoexec are supplied. No add-on preferences are persisted. No `bpy` wheel install, Rigify enable, script remapping, geometry cleanup or render setting changes touch production assets.
